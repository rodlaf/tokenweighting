\section{Experiments}\label{sec:experiments}

\subsection{Goal and Experimental Philosophy}

Our empirical goal is to test whether intrinsic token weighting changes credit allocation in a useful way under sparse sequence-level rewards. We do \emph{not} claim that the present benchmark is a substitute for large-scale LLM RLVR. Instead, we use a controlled, fully reproducible testbed that exposes token-level semantics directly: each trajectory contains known reward-relevant and reward-irrelevant positions, allowing us to measure where the weighting rules place their mass.

This choice reflects the current state of the project. The code in \texttt{experiment/} is intended to be easy to inspect, easy to run on CPU, and suitable for rapid ablations. It provides a clean platform for validating the core credit-allocation idea before porting it into a heavyweight transformer RL stack.

\subsection{Benchmark Tasks}

\paragraph{Arithmetic trace.}
The prompt consists of two integers $a,b \in \{0, \ldots, 7\}$. The model generates a length-five trajectory with two filler tokens followed by three semantically important symbolic decisions: a carry token, a parity token, and a coarse answer bucket. The reward is $1$ if and only if all three relevant tokens are correct. We pair this task with an RLOO baseline, since grouped leave-one-out normalization is the simplest critic-free objective for sparse binary rewards.

\paragraph{Program trace.}
The prompt consists of a symbolic operation and a small value bucket. Again the trajectory length is fixed to five, with two filler tokens followed by an operation token, argument token, and output token. The reward is $1$ iff the generated symbolic trace matches the verifier's expected triple. We pair this task with GRPO-style group normalization, which yields a stronger relative baseline in this setting.

Both tasks are verifiable, deterministic, and expose exactly which token positions are semantically important. This makes it possible to evaluate not just success rate but also a \emph{token mass alignment} metric: the fraction of the normalized token weight assigned to important positions.

\subsection{Model and Training Setup}

The policy is a contextual autoregressive model implemented in NumPy. At each step it consumes a prompt vector, the previous token, and a learned position embedding; these are mapped to a tanh hidden state and then to next-token logits with a linear output head. We train with plain score-function policy gradients under either RLOO or GRPO baselines. There are no critics, reward models, auxiliary token scorers, or tree rollouts.

For the paper runs we use hidden size $64$, group size $4$, learning rate $0.10$, gradient clipping at $5.0$, and three random seeds. Arithmetic experiments run for 300 update steps with 16 prompts per step under RLOO. Program-trace experiments use the same schedule under GRPO-style normalization. All runs are launched via YAML configs in \texttt{experiment/configs/}; the exact commands are documented in \texttt{experiment/README.md}.

\subsection{Compared Methods}

We compare three weighting rules under fixed outer objectives:
\begin{itemize}
    \item \textbf{Uniform}: standard critic-free token broadcasting.
    \item \textbf{Surprisal}: token weights proportional to negative log-probability.
    \item \textbf{Entropy reduction}: token weights proportional to local entropy drop.
\end{itemize}
On arithmetic we compare these under RLOO; on program traces we compare them under GRPO. This isolates the contribution of the token weighting rule from the choice of outer baseline.

\subsection{Metrics}

We report four metrics.
\begin{enumerate}
    \item \textbf{Greedy accuracy}: reward under greedy decoding.
    \item \textbf{Pass@4}: success rate over four sampled completions.
    \item \textbf{Important-mass mean}: average fraction of token weight placed on semantically important positions.
    \item \textbf{Final weighted score-variance proxy}: within-trajectory variance of weighted token score norms at the end of training.
\end{enumerate}
The first two measure task performance. The third measures whether the weighting rule actually concentrates mass on reward-relevant decisions. The fourth is diagnostic only and should not be over-interpreted as a theorem-backed variance estimator.

The results support three observations.

\paragraph{First, intrinsic weighting can improve success rates over uniform token updates.}
On arithmetic, surprisal weighting improves pass@4 from 29.2\% to 32.7\% while keeping greedy accuracy unchanged. On program traces, both intrinsic weighting rules improve over uniform, with entropy reduction yielding the strongest gains: greedy accuracy rises from 13.3\% to 23.3\% and pass@4 from 27.1\% to 43.4\%.

\paragraph{Second, better performance tracks better alignment of token mass with semantically important positions.}
The strongest program-trace method, entropy reduction, assigns 86.5\% of its token mass to the three important positions, compared with 60.0\% under uniform weighting. Surprisal weighting also shifts mass toward important positions in the program setting. This is exactly the behavior we want from a credit-allocation prior: not merely different gradients, but gradients focused on the right decisions.

\paragraph{Third, gains are not explained by naive variance reduction.}
The better-performing intrinsic methods often have \emph{higher} values of the weighted score-variance proxy than the uniform baseline. This is especially clear on the program-trace task, where entropy reduction dramatically improves performance while also increasing the variance proxy by several orders of magnitude. The natural interpretation is that intrinsic weighting is not simply damping the gradient. Instead, it is reallocating update mass toward positions that matter more, even if those positions are individually sharper or noisier.

\subsection{Task Dependence}

The two tasks exhibit different winners. Arithmetic favors surprisal, whereas program traces favor entropy reduction. This is informative rather than problematic. The arithmetic task rewards symbolic choices that are comparatively rare under the policy but not necessarily followed by an immediate collapse in continuation entropy. The program-trace task, by contrast, has explicit branch-closing tokens, making entropy reduction a stronger proxy for commitment. These differences suggest that intrinsic token weighting should be treated as a family of credit priors rather than a single universally optimal rule.

\subsection{Reproducibility and What Comes Next}

All numbers in this section are reproducible from the repository without GPU dependencies. The benchmark therefore serves as a transparent reference implementation of intrinsic token weighting. The obvious next step is to port the same weighting rules into a transformer-based RLVR stack with real math and code benchmarks. We view the present controlled benchmark as a necessary first stage: it verifies that the weighting rules can move update mass toward known important decisions and improve downstream success in settings where the token semantics are fully observable.
